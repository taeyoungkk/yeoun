# Frontend API Integration Priority

## 목적

프론트엔드 API 연동 작업의 우선순위를 정리한다.

- 기준일: 2026-03-20
- 기준 범위: `Frontend/yeoun-client`, `Backend/src/main/java/com/yeoun`
- 원칙: 기존 목업 데이터는 제거하지 않고, 실연동 가능 구간부터 점진적으로 전환한다.

## 우선순위 요약

| 우선순위 | 영역 | 이유 | 선행 조건 |
| --- | --- | --- | --- |
| P0 | 여행 생성/상세/시작/종료/위치로그 업로드 스펙 정합성 수정 | 이미 프론트에서 호출 중이지만 백엔드와 request/response shape가 맞지 않아 실사용 리스크가 큼 | 프론트 API 타입 정리 |
| P0 | 공통 API 클라이언트 경로 정리 | `baseURL`과 상대 경로가 혼용되어 일부 호출이 `/api/v1/api/v1/...`가 될 수 있음 | 없음 |
| P1 | 친구 기능 신규 구축(화면 + API 연동) | 백엔드 구현은 완료됐지만 프론트에는 친구 전용 화면과 API 모듈이 모두 없음 | 화면 설계, API 모듈 추가 |
| P1 | 여행 멤버/초대 연동 | 현재 초대 UI는 전부 목업이며 실제 여행 플로우와 직접 연결됨 | 친구 연동 또는 사용자 검색 전략 확정 |
| P1 | 사진 목록/상세/메모/제외 복원 | 백엔드 구현 완료, 현재 사진 앨범 화면은 목업 의존 | 사진 API 모듈 추가 |
| P1 | 타임라인 조회/이벤트 상세/이벤트 메모 | 백엔드 구현 완료, 리포트/앨범/기록 화면의 핵심 데이터 소스 | 사진/여행 상태 흐름 점검 |
| P2 | 비용 CRUD | 화면은 있으나 전부 스토어 목업, 백엔드는 구현 완료 | 비용 API 모듈 추가 |
| P2 | 타임라인 생성 작업 요청 | 조회 연동 뒤에 붙이는 것이 안전 | 작업 상태 조회 API 부재 확인 필요 |
| P2 | 닉네임/이메일 중복 확인 | 회원가입 UX 개선용, 기능 중요도는 중간 | 회원가입 폼 검증 흐름 정리 |
| P3 | 리포트 | 백엔드 미구현 | 백엔드 구현 필요 |
| P3 | 정산 | 백엔드 미구현 | 백엔드 구현 필요 |
| P3 | 결제내역 후보 | 백엔드 미구현 | 백엔드 구현 필요 |
| P3 | 공유 앨범 | 백엔드 미구현 | 백엔드 구현 필요 |
| P3 | 권한 상태 조회/갱신 | 백엔드 미구현, 현재는 OS 권한만 직접 처리 중 | 백엔드 구현 필요 |
| P3 | 위치 로그 조회/일자별 경로 조회 | 백엔드 미구현 | 백엔드 구현 필요 |
| P3 | 공통 비동기 작업 상태 조회 | 백엔드 미구현 | 백엔드 구현 필요 |
| P3 | 알림 | 명세만 있고 구현 확인 불가 | 백엔드 구현 필요 |

## 권장 작업 순서

### 1. 공통 정합성 수정

- `apiClient`의 `baseURL` 기준을 고정한다.
- 모든 API 모듈이 상대 경로만 쓰도록 맞춘다.
- 공통 응답 형식을 실제 백엔드 응답과 맞춘다.

### 2. 이미 연결된 여행 플로우 정상화

- 여행 생성
- 여행 상세 조회
- 여행 시작/종료
- 위치 로그 업로드

이 구간은 이미 화면에서 사용 중이라, 먼저 고쳐야 실연동 가치가 생긴다.

### 3. 목업 유지형 실연동 전환 1차

- 친구 기능 신규 구축
- 여행 초대/멤버
- 사진
- 타임라인 조회

화면은 유지하고, 실패 시 기존 목업으로 fallback 되도록 전환하는 방식이 적합하다.

### 4. 목업 유지형 실연동 전환 2차

- 비용 CRUD
- 결제 관련 화면 구조 정리

정산/결제내역 후보는 백엔드가 아직 없으므로 비용만 먼저 붙이는 편이 합리적이다.

## 화면 기준 우선순위

| 화면 | 현재 상태 | 우선순위 |
| --- | --- | --- |
| 로그인/회원가입/비밀번호 재설정 | 실연동 있음, dev fallback 있음 | 유지 |
| 마이페이지/프로필 수정/설정 | 실연동 있음, 일부 경로 수정 필요 | P0 |
| 여행 시작 화면 | 실연동 시도 중, 초대는 목업 | P0/P1 |
| 여행 기록 화면 | 여행 시작/종료는 호출, 내부 이벤트는 목업 | P1 |
| 사진 앨범 화면 | 전부 목업 스토어 | P1 |
| 홈 과거 여행 섹션 | 목록 조회 연동 있음, 응답 매핑 보정 필요 | P1 |
| 친구 화면 | 현재 없음, 신규 구축 필요 | P1 |
| 결제 화면 | 전부 목업 스토어 | P2 |
| 리포트 화면 | 전부 목업 스토어 | P3 |

## 구현 원칙

- 목업 삭제 금지
- 실연동 실패 시 기존 목업 fallback 유지
- API 모듈 추가 후 화면 전환
- 백엔드 미구현 API는 프론트 선개발하더라도 mock adapter로 유지
